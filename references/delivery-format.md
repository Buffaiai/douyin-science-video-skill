# 交付格式

每期两份 markdown：`SCRIPT.md`（做完片子的依据）与 `DELIVERY.md`（发布用）。
`scripts/new_episode.sh` 已经生成带空格的骨架，照着填。

## SCRIPT.md

```markdown
# 第 N 期 · <母题名>（<中文片名>）

选题：情感悬念「」 × 硬核机制「」 × 人文升华「」
成片规格：1920×1080 / 30fps / <帧数> 帧（<秒>）/ 横屏
水印（右上角常驻）：<四字主题>
视觉母题（单一贯穿）：<母题>，配 <道具1>、<道具2>…。全片无小人。

## 分场文案（字幕逐块）

### 1. hook · 330f（11s）
画面：<这一场的视觉动作，写清随时间怎么变>
- <字幕第 1 句>
- <字幕第 2 句>

### 3. classic · 450f（15s）
画面：…；角标「只标方向 · 不给倍数」；印章「…」。**不标任何百分比。**
- …
- 出处：Iyengar & Lepper · 2000 · JPSP · PMID 11138768

## 事实核查清单（EuropePMC 在线核实，<日期>）

| 论断 | 出处 | 状态 |
|---|---|---|
| <一句可核实的论断> | <作者 (年). 期刊. DOI, **PMID**> | 摘要全文核实 ✓ / 非 OA 只取到首句 → 只讲方向 / 查不到 → 弃用 |

**刻意不写进文案的**：
- <取不到却被流行说法广泛传播的数字> —— 属"我记得"级别，不写
```

要点：每场的「画面」行要写清**状态如何随时间变化**（越亮、翻倍、被压暗），因为这正是写组件的依据；字幕里被高亮的关键词在组件里用 `accents` 传。

## DELIVERY.md

```markdown
# 交付文案 · 第 N 期《<中文片名>》（<母题>）

## 发布标题（≤30 字，带钩子）
主推（19 字）：「Vibe知识大赏」<标题>
备选 1（18 字）：「Vibe知识大赏」<标题>
备选 2（21 字）：「Vibe知识大赏」<标题>

## 正文
<钩子一句 → 反常识事实 → 机制一句 → 金句收尾 → 一行出处 → 话题标签>

出处：<作者, 年, 期刊 (PMID …)>；…

#Vibe知识大赏 #<主题标签> #心理学 #认知偏差 #自我认知 @抖音科技

## 发布提醒
- 封面建议：<指到具体场次与秒点，说要哪一帧为什么有效>
- 评论区置顶提问：**<把选题变成观众自证的问题>**
- 本期争议点：<公开打折了哪个流行说法 + 可直接回复的原始数据>

## 质检记录
- **成片**：1920×1080 / 30fps / <帧数> 帧 / <秒>，H.264 CRF15 + JPEG100，<大小>，<码率> → `<日期目录>/<片名>.mp4`
- **色域标签**：`yuv420p / tv / bt709`，SPS 三项=1
- **画面亮度**：<N> 点抽测 YAVG min/mean/max，无 <35 段落；第 0 帧即有完整内容
- **人物合规**：全片无小人。母题＝…
- **QA**：<几张静帧 + 几张成片抽帧 + 实际修掉了什么>
- **文献**：本轮核实 <N> 条 — <PMID 与取值限制>
- **主动弃用**：<查不到的东西>
- **音频素材**：<混了哪个文件，截到多长>
- 中间产物已清理，工程源码保留可复渲
```

标题字数**含前缀与标点**一起数；正文字数不必刻意，但结构要能一眼读完；话题标签 4~6 个，`@抖音科技` 是这条赛道的固定 @。

## 归档与清理

- 成片归档到 `<工作目录>/YYYY-MM-DD/<中文片名>.mp4`（日期 = 交付日）。
- 交付当轮就删：抽帧 PNG、contact sheet、raw/graded 中间 mp4、`<project>/out/` 内容、/tmp 中间件。
- 保留：最终成片 + 工程源码 + 两份 md。
- 中间件一律写到 /tmp，不堆在项目目录（历史上一期光测试产物就 83 MB）。
- 动旧项目里已有的 `out/` 成片前先问。
